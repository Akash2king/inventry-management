# UX Fix Plan: Backend Interaction & User Flows

## Problem Summary
The app has solid functionality but ~20 critical UX gaps where users get stuck (infinite spinners, swallowed errors, no retry), lose work (no unsaved-changes warnings), or get confused (silent redirects, raw stage numbers, no feedback after actions).

---

## Phase 1: Critical — "User Gets Stuck" Fixes

### 1A. Add React Error Boundary for lazy-loaded routes
**File:** `src/router.jsx` (new component) + `src/components/ErrorBoundary.jsx` (new file)
- Create a class-based `ErrorBoundary` component with a "Something went wrong. Try refreshing." message and a retry button.
- Wrap `SuspensePage` with `<ErrorBoundary>` so if any lazy chunk fails to load (network disruption), the user sees a recovery screen instead of a white crash.
- Also wrap the main `<RouterProvider>` in `App.jsx`.

### 1B. Fix infinite-spinner-on-error in RecordDetail and RecordEdit
**Files:** `src/pages/records/RecordDetail.jsx`, `src/pages/records/RecordEdit.jsx`
- Both pages call `fetchOne(id).catch(() => {})` then check `if (!r || String(r.id) !== String(id))` — when fetch fails, this stays true forever → permanent spinner.
- **Fix:** Use the `error` and `isLoading` from `recordStore` to distinguish loading from error. Show an error banner with a "Retry" button when `isLoading === false && !activeRecord`.

### 1C. Fix silent error swallowing in RecordList and WorkflowQueue
**Files:** `src/pages/records/RecordList.jsx`, `src/pages/workflow/WorkflowQueue.jsx`
- `RecordList`: `fetchAll(filters).catch(() => {})` — if API fails, user sees "No records" with no indication of failure.
- **WorkflowQueue`: `fetchQueue().catch(() => {})` — fails silently, shows "Your queue is clear".
- **Fix:** Both stores already track `error` state (`recordStore.error`, `workflowStore.error`). Add an error banner with retry button when `error` is set and data is empty.

### 1D. Add error feedback for role-based access redirects
**File:** `src/router.jsx`
- `GmOnly`, `ManagerOrGmOnly`, and `PasswordGate` silently redirect with `<Navigate>`.
- **Fix:** Dispatch a toast ("You don't have permission to access that page.") before redirecting. Use `useUiStore().showToast()`.

## Phase 2: High Priority — Data Integrity & Feedback

### 2A. Add debounce to search inputs (3 files)
**Files:** `src/pages/records/RecordList.jsx`, `src/pages/audit/AuditLogPage.jsx`, `src/pages/gm/GmConsole.jsx`
- All fire API calls on every keystroke (RecordList vendor search, AuditLog search, GmConsole employee search).
- **Fix:** Create a `useDebouncedValue` hook in `src/utils/useDebouncedValue.js` (~300ms delay). Use it in all three pages so the API only fires after the user stops typing.

### 2B. Fix token refresh race condition
**File:** `src/platform/installBrowserApi.js`
- If multiple requests hit 401 simultaneously, each independently calls `tryRefreshAccess()`, resulting in multiple refresh calls racing.
- **Fix:** Add a `_refreshPromise` singleton variable. When a 401 triggers a refresh, check if a refresh is already in-flight and reuse the same promise instead of starting a new one.

### 2C. Remove broken `updateProfile` from authStore
**File:** `src/store/authStore.js` (lines 92-103)
- `updateProfile` calls `window.api.auth.updateProfile()` but this endpoint doesn't exist in `installBrowserApi.js`. If anything calls it, it will throw "API not available".
- **Fix:** Remove the `updateProfile` method. Check all usages (grep) — if nothing calls it, just delete it.

### 2D. Add success toast after password change
**File:** `src/pages/ChangePassword.jsx` (line 81-82)
- After successful password change, the user is immediately redirected with no feedback.
- **Fix:** Call `showToast("Password updated successfully.", "success")` before navigating, or show a brief success screen for 1.5s then redirect.

### 2E. Clear login error when user starts typing
**File:** `src/pages/Login.jsx` (lines 197-225)
- Error banner persists until re-submit, even if user has fixed their input.
- **Fix:** Add `setError("")` inside the `onChange`/`onInput` handlers for username and password fields.
- Also remove the redundant `onInput` handlers (keep only `onChange`).

### 2F. Add network offline detection banner
**Files:** `src/components/NetworkStatusBanner.jsx` (new), `src/components/layout/Layout.jsx`
- Create a banner component that listens to `navigator.onLine` and `online`/`offline` events.
- Render it in `Layout.jsx` above the page content. Shows "You are offline — some features may be unavailable." when disconnected.

## Phase 3: Medium Priority — UX Friction

### 3A. Use stage labels instead of raw numbers in RecordList filter
**File:** `src/pages/records/RecordList.jsx` (lines 234-240)
- Stage dropdown shows `1, 2, 3, 4, 5` — users don't know what these mean.
- **Fix:** Import `STAGE_LABELS` from `src/pages/dashboardConstants.js` and render descriptive labels.

### 3B. Use `navigate(-1)` for RecordDetail back button
**File:** `src/pages/records/RecordDetail.jsx` (line 89)
- Back button always goes to `/records`, even if user came from queue or notification.
- **Fix:** Use `navigate(-1)` but with a fallback: check `window.history.length > 1`, if not, navigate to `/records`.

### 3C. Add unsaved-changes warning on RecordEdit
**File:** `src/pages/records/RecordEdit.jsx`
- Cancel button and browser-back silently discard all edits.
- **Fix:** Add a `isDirty` state (track via `react-hook-form`'s `formState.isDirty`). Show a confirmation dialog (`window.confirm`) when navigating away with unsaved changes. Use `useBeforeUnload` from React for browser close/refresh.

### 3D. Fix ChangePassword error display inconsistency
**File:** `src/pages/ChangePassword.jsx` (lines 181-184)
- Error div renders only `<span>{error}</span>` but Login.jsx uses `<IconAlert />` + `<span>`.
- **Fix:** Add the same `<IconAlert />` SVG for consistency.

### 3E. Fix SecuritySessionsPage loading indicator
**File:** `src/pages/security/SecuritySessionsPage.jsx` (line 62)
- Uses plain text "Loading..." instead of the `<div className="spinner" />` used everywhere else.
- **Fix:** Replace with the standard spinner component.
